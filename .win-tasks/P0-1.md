B. rune-core 第一批移植（对照 native/Sources/RuneCore/State.swift 与 test/reference/core/state.js、engine.js 第 8-32、189-190 行）
- JSON 值用 serde_json::Value（Map 需 preserve_order）。
- 实现并导出：defaults/initial_state、validate_config、validate(state)、verified、same_identity（按 UTF-16 code unit 相等，即 Rust 的 String ==，无归一化）、authorization(identity)、consent(identity, lead)、scope(email)、json_string（等价 JSON.stringify：无空格，键按插入顺序，不转义 /；数字格式必须与 JS 一致——整数无小数点，大数不用指数，特殊注意 lead 为整数）、digest、sha256、is_boolean/number/integer（JS 语义：整数判定 |n| ≤ 2^53-1 且无小数）。
- inventory_revision(count, credits)：排序必须等价 JS `localeCompare()` 默认英文 ICU 排序。决策（由协调者给定，不要引入 ICU 数据）：实现一个最小等价比较器——
  1) 主键：按 Unicode 规范化 NFD 后去掉组合记号（Mn）得到"基字母"序列，字符映射到 ICU 根排序的一级权重近似：标点/符号 < 数字 < 字母（字母按 a-z 不分大小写）；
  2) 次键：重音（有组合记号 > 无）；
  3) 三键：大小写（小写 < 大写）；
  4) 相等时保持原顺序（稳定排序）。
  向量 native-hash-vectors.json 的 ID 集 ["a","A","é","e\u0301","/"] 期望结果 ["/","a","A","é","é"]（组合与预组合 é 比较相等，稳定保序）。用 unicode-normalization crate 做 NFD。在 README 中标注这是 ICU 英文排序的受限等价实现，覆盖范围由向量约束。
- 测试：读取 ../test/contracts/native-hash-vectors.json（相对 crate 用 CARGO_MANIFEST_DIR 定位），逐条断言 scope/authorization/consent/inventoryRevision 全部相等。另加单元测试：json_string 对 [5, [["a",1000]]]、带 "/" 和中文的字符串、以及 10 vs 10.0 的输出与 JS 一致。
