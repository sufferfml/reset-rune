A. rune-platform::paths（技术方案 §7）
- data_root(mock: bool) -> PathBuf：通过 SHGetKnownFolderPath(FOLDERID_LocalAppData) 解析（windows crate feature Win32_UI_Shell + Win32_System_Com），拼 "Bottled Reset Rune"；mock 时加子目录 "simulation"；环境变量 RESET_RUNE_DATA_DIR 非空时覆盖根目录（仍按 mock 加 simulation）。
- user_sid_digest() -> String：OpenProcessToken + GetTokenInformation(TokenUser) → ConvertSidToStringSidW → sha256 十六进制前 16 位（Win32_Security + Win32_Security_Authorization）。
- pipe_name(mock) -> String：`\\.\pipe\reset-rune.<sid摘要>.v1` + mock 时 `.mock`。
- task_name(mock) -> String：`Bottled Reset Rune` + mock 时 ` (Mock)`；放在任务文件夹 `\Bottled Reset Rune\`。

B. rune-platform::scheduler（技术方案 §8）—— 用 COM Task Scheduler 2.0（windows crate features Win32_System_TaskScheduler, Win32_System_Com, Win32_System_Ole, Win32_System_Variant）
- register(spec) ：当前用户、LogonType = TASK_LOGON_INTERACTIVE_TOKEN、RunLevel = LUA（最低权限）；Actions = Exec(path, args, working_dir)；Settings：ExecutionTimeLimit "PT0S"、DisallowStartIfOnBatteries false、StopIfGoingOnBatteries false、RunOnlyIfIdle false、RunOnlyIfNetworkAvailable false、WakeToRun false、MultipleInstances IgnoreNew、AllowDemandStart true、StartWhenAvailable true、RestartCount 3 / RestartInterval PT1M；Triggers：仅当 spec.logon_trigger 为 true 时加 LogonTrigger(UserId=当前用户)。
- read_xml(name) -> String：回读任务 XML；提供 verify(name) 校验上述每个设置在 XML 中的实际值（不要只看注册成功）。
- run(name) / stop(name) / state(name) / unregister(name)。
- 注意：标准用户在 `\Bottled Reset Rune\` 文件夹下注册自己的任务应无需管理员；若 RegisterTaskDefinition 返回 E_ACCESSDENIED，记录为 "task-scheduler-denied" 并在报告中说明。
- 测试（只用 `(Mock)` 名称，结束时必定 unregister，即使失败也清理）：注册 → read_xml 包含 PT0S、DisallowStartIfOnBatteries=false、StopIfGoingOnBatteries=false、IgnoreNew、InteractiveToken、LeastPrivilege → run 一个会在 3 秒后退出的 cmd（例如 PowerShell -Command Start-Sleep 3，或 rune-app 的 --probe 子命令）→ state 为 Running → 等待结束 → unregister → 再查询应为 not found。logon_trigger=false 时 XML 不含 LogonTrigger；true 时含。

C. rune-app 最小托盘样机（仅 P0 用于资源基线；P3 再做完整面板）
- `reset-rune.exe --tray --mock`：Shell_NotifyIconW 添加图标（先用系统 IDI_APPLICATION，ICO 资源在 P3 加入）、tooltip "Bottled Reset Rune (mock)"；右键菜单：Open / Quit（Open 暂时弹 MessageBox）；处理 TaskbarCreated 消息重建图标（Explorer 重启）；消息循环为 GetMessageW 阻塞，无计时器。features：Win32_UI_WindowsAndMessaging, Win32_UI_Shell, Win32_Graphics_Gdi。
- `reset-rune.exe --probe-idle <seconds>`：一个无 UI 的进程，仅 WaitForSingleObject 睡眠（模拟后台空闲）。
- `reset-rune.exe --version`、`--help`。
- rune-app 的 [package.metadata] 或 build 配置：release profile opt-level="z"/s、lto=true、codegen-units=1、panic=abort、strip=true（在 workspace Cargo.toml 的 [profile.release] 中设置）。

D. 资源基线采样脚本 scripts/measure-windows-idle.ps1
- 参数：-Exe <path> -Seconds <n>（默认 60；P0 先跑 60 秒，30 分钟留到 P5）。启动 `--tray --mock` 与 `--probe-idle` 两个进程，用 Get-Counter 或 Get-Process 每 5 秒采样 CPU 时间增量、PrivateMemorySize64、WorkingSet64、Handles、Threads，输出 CSV 到 .build\logs\idle-<timestamp>.csv 并打印汇总（平均 CPU%（按单核）、峰值 Private Bytes），最后结束两个进程。报告采样精度（Get-Process CPU 时间分辨率）。
- 在报告中给出：release 构建的 reset-rune.exe 大小（字节）、依赖的非系统 DLL（用 dumpbin /dependents 若有，否则用 PowerShell 读 PE 导入表或 `where.exe` 说明）、60 秒空闲的平均 CPU 与 Private Bytes。
