1. 依赖与打开参数
   - rusqlite bundled（已在 workspace 锁定 0.41.1）。在报告中记录 rusqlite::version() 返回的 SQLite 版本，必须 ≥ 3.51.3（WAL-reset 缺陷修复），否则升级 rusqlite。
   - 打开：journal_mode=WAL、synchronous=FULL、busy_timeout=5000、foreign_keys=ON、wal_autocheckpoint 保持默认；单连接，不开连接池；不做周期 vacuum。
2. 目录与文件安全（技术方案 §7）
   - SqliteStateStore::open(dir: &Path)：dir 必须为绝对路径；不存在则创建；必须是常规目录；拒绝 reparse point（FILE_ATTRIBUTE_REPARSE_POINT，用 std::fs::symlink_metadata）；拒绝 UNC（\\?\UNC\ 或 \\server\）与网络驱动器（GetDriveTypeW == DRIVE_REMOTE，windows crate feature Win32_Storage_FileSystem）。错误码 insecure-data-directory。
   - 数据库文件 state.db；若存在须为常规文件且非 reparse point，否则 insecure-state-file。
3. schema（PRAGMA user_version = 1）
   - state(id INTEGER PRIMARY KEY CHECK(id=1), revision INTEGER NOT NULL, json TEXT NOT NULL, updated_at INTEGER NOT NULL)
   - platform_settings(key TEXT PRIMARY KEY, value TEXT NOT NULL, updated_at INTEGER NOT NULL)
   - open 时：user_version==0 → 建表并设 1；==1 → 直接用；>1 → 错误 unsupported-schema（不降级、不重建）。
4. API（实现 rune_core::StateStore）
   - read() -> Value：无行时返回 rune_core::initial_state()（经 validate）；有行时解析 json 并 validate；解析失败 → unsupported-state（不删库）。
   - write(&Value)：BEGIN IMMEDIATE；读当前 revision；UPSERT revision+1、json=json_string(value)（用 rune_core::json_string 保证键序）、updated_at=now ms；COMMIT。任何 SQLite 错误 → state-write-failed，并保持旧值可读。
   - revision() -> Option<i64>；platform_get(key) -> Option<String>；platform_set(key, value)。
   - 提供 backup_to(path)：用 rusqlite::backup::Backup 做一致性备份（不是复制文件）。
5. 测试（tests/）
   - 基本：open→read 返回 initial_state；write 两次 revision 1→2；重开读到最新；json 键序与 json_string 一致。
   - 掉电/被杀：spawn 子进程（cargo test 内用 std::process::Command 运行同一测试二进制的隐藏子命令，或单独写 examples/killer.rs）在循环中反复 write，父进程 200ms 后 kill；重开数据库必须能打开，读到的 state 要么是某次完整写入的值，revision 单调且与 json 对应（json 内含 revision 标记字段便于核对，例如 config.lead 轮换与 events 计数）。重复 10 次。
   - 磁盘满：PRAGMA max_page_count=2（或极小）后写大 state → write 返回 state-write-failed，随后 read 仍返回旧值。
   - 损坏：向 state.db 头部写入随机字节 → open 返回 Err（unsupported-state 或 insecure-state-file），绝不重建；确认文件未被修改（hash 相同）。
   - WAL 存在：写入后不 checkpoint 直接 drop 连接（模拟崩溃前 WAL 未合并）→ 重开读到最新值。
   - 目录检查：相对路径、UNC 路径（\\localhost\c$\...）、符号链接目录（用 mklink /D 需管理员，可改用 junction：New-Item -ItemType Junction 不需管理员）→ open 均返回 insecure-data-directory。
   - schema：手工把 user_version 设为 7 → open 返回 unsupported-schema。
