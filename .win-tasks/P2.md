2a. rune-platform 基础设施
- lock.rs：ExecutorLock / LifecycleLock —— 文件独占锁（CreateFileW 独占 share=0 或 LockFileEx），文件位于 data_root 下 executor.lock / lifecycle.lock；被占用时错误码 executor-busy / service-update-in-progress；Drop 释放。
- pipe.rs：命名管道服务端与客户端。
  - 服务端：CreateNamedPipeW(PIPE_ACCESS_DUPLEX | FILE_FLAG_FIRST_PIPE_INSTANCE | FILE_FLAG_OVERLAPPED, PIPE_TYPE_BYTE | PIPE_READMODE_BYTE | PIPE_REJECT_REMOTE_CLIENTS)，显式 SECURITY_ATTRIBUTES：DACL 仅当前用户 SID (GENERIC_READ|GENERIC_WRITE) + SYSTEM + Administrators（必要系统主体），不含 Everyone/Anonymous。首实例被占用 → 错误 pipe-busy（不连接未知执行器）。
  - 帧：4 字节小端长度 + JSON（含 "v":1, "id", "op", "params" / 响应 "id","ok","result"|"error"），单帧 ≤ 1 MiB，超限断开；每连接读超时 15 秒、最多 4 KiB 请求体（订阅连接除外）。
  - 客户端：CreateFileW 打开，SetNamedPipeHandleState；连接后用 GetNamedPipeServerProcessId 取服务端 PID 并核对其可执行文件路径是否在受信目录（data_root\runtime\ 下或与自身 exe 相同目录），不匹配 → untrusted-executor。
  - 操作：status、refresh、config(patch)、bind(consent)、subscribe（服务端按 revision 推送 view，慢客户端有界合并：只保留最新一帧，不排队）、ping。不提供任意执行/文件访问。
- timer.rs：单一可重排 waitable timer（CreateWaitableTimerExW，无 HIGH_RESOLUTION、无 resume 标志）；arm(at_utc_ms) / disarm；触发回调到 worker 队列。
- events.rs：系统事件 → worker 队列：电源恢复（RegisterPowerSettingNotification 或 WM_POWERBROADCAST PBT_APMRESUMEAUTOMATIC）、时钟变化（WM_TIMECHANGE）、网络连接（INetworkListManager 事件或 NotifyAddrChange/NotifyIpInterfaceChange 简化实现）。事件只触发"已到期或此前失败"的任务（遵循 ServiceCoordinator.systemEvent 语义）。
- 测试：锁互斥（两个进程）；管道 ACL（用 GetSecurityInfo 回读 DACL 断言无 Everyone）、首实例占用返回 pipe-busy、超大帧断开、并发客户端；timer 到期触发一次、重排后旧时间不触发。

2b. worker（rune-app --serve [--mock]）
- 移植 RuneService/Service.swift 的 ServiceCoordinator：status/refresh(manual)/configure/bind/reschedule/systemEvent/close；业务执行队列为单线程（channel 驱动），独占 SqliteStateStore 与 Engine；IPC 与事件线程只投递消息。
- 来源：mock → MockSource（移植 RuneService/MockSource.swift，sample-inventory 存到 platform_settings 或 data_root\sample-inventory.json）；live → CodexSource(allow_consume=true)。
- 启动顺序：ExecutorLock → 打开 SQLite → Engine → 管道服务端 → 写 connection.json（{"pipe":..., "pid":..., "mode":..., "protocol":1, "version":"0.1.2"}，0600 等价：DACL 仅当前用户）→ 事件注册 → 初始 refresh(false) → 若 config.startup 为真则确保计划任务有登录触发器。
- 退出：收到 stop 操作 / CTRL 事件 → 停止接受新连接 → 等待当前事务 → engine.close()（回收 Codex 子进程）→ 删除 connection.json → 释放锁。
- 通知：config.notify 且结果 reset 时，先用最简单的方式：Shell_NotifyIconW NIF_INFO 气泡（若托盘不在同一进程则通过管道 push 一个 "notify" 事件由托盘显示）；完整 Toast/AUMID 留 P3。
- 暂停持久化失败处理（技术方案 §3 末段）：configure(enabled=false) 写入失败时，把计划任务标记为隔离（platform_settings quarantine=原因，并调用 scheduler.stop 抑制重启），返回错误 pause-not-persisted，view 中带 error。

2c. CLI（rune-app 默认角色；移植 RuneCommand/main.swift 命令语义）
- 命令：status | start | stop | restart | refresh | doctor | ui | enable --confirm | bind --confirm | pause | config <lead|language|appearance|startup|notify> <value> | uninstall-service | upgrade | rollback | --version | --help；通用 --mock。
- start：LifecycleLock → 若无活动后台则注册/确保计划任务（Exec = 自身 exe `--serve [--mock]`，WorkingDirectory=data_root；开发模式 RESET_RUNE_DEVELOPMENT=1 直接用当前 exe 路径，否则 P4 的 runtime/current）→ scheduler.run → 轮询 connection.json + ping 最多 12 秒。
- stop：scheduler.stop（抑制重启）→ 管道发 stop → 等待退出 → 校验 executor.lock 可获取。
- pause：管道 config{enabled:false}。enable/bind：先 status，无 consent 则 refresh，再带 consent 发送。
- uninstall-service：stop → 任务注销（含 (Mock)）→ 写 config.startup=false → 删除 runtime 目录 → 打印 "Background service removed; journal and Codex login retained."。
- upgrade/rollback：P4 实现，这里打印 not-implemented-until-p4 并退出 2。
- 输出：JSON（sorted keys, pretty），去掉 consent；错误到 stderr "Bottled Reset Rune: <code>" 退出 1。
- 子命令 --probe-idle、--tray 保留。
- 决策：exe 子系统 —— 用 /SUBSYSTEM:WINDOWS 会让 CLI 无控制台输出；用 CONSOLE 则 --serve/--tray 从计划任务/快捷方式启动会闪窗。采用：保持 CONSOLE 子系统，但 --serve 和 --tray 启动时若发现自己拥有控制台窗口（GetConsoleWindow 非空且是自己创建的，即 GetWindowThreadProcessId 等于本进程）则 FreeConsole；计划任务 Exec 用 CREATE_NO_WINDOW 效果由 Task Scheduler 隐藏（任务设置 Hidden=true）。在报告中记录是否仍有闪窗。
