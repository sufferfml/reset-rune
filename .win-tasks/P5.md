C. 故障与边界（§5 业务与安全 / 生命周期）—— 每项写明命令、观察、结论
1. 睡眠/断网：无法在无人值守下真实睡眠；替代：用 RESET_RUNE_TEST 开关或直接向 worker 投递"模拟唤醒"事件（若 events.rs 有测试入口），验证只处理已到期/失败任务；记录为"模拟事件验证，非真实睡眠"。
2. 崩溃：在 intent 已提交、consume 未返回时 kill worker（mock 来源增加可控延迟开关 RESET_RUNE_MOCK_CONSUME_DELAY_MS）→ 重启后 operation 保持原 key/id 恢复，不产生第二笔；验证 requests 日志只有一个 key。
3. 权限与损坏：数据目录放在只读 ACL 目录 → start 失败并给出错误码，不重建；state.db 损坏 → worker 拒绝启动，CLI status 报 unsupported-state，文件未修改。
4. 双入口互斥：同时启动两个 `--serve` → 第二个 executor-busy；同时两个 `start` → 一个 service-update-in-progress 或正常等待。
5. 暂停持久化失败隔离：用 max_page_count 或只读 db 模拟 pause 写入失败 → 返回 pause-not-persisted、计划任务被禁用（schtasks /Query 显示 Disabled）、worker 内存门禁生效（后续 tick 不发送）。
6. 卸载与重装：uninstall-service 后 state.db 保留；重新 install + start 后 enabled 仍为 false（不因旧 enabled=true 自动恢复——验证 uninstall 已写 config.enabled=false 或等价的重新确认状态）。
7. 干净设备安装：在一个全新 Windows 用户账户（New-LocalUser 需管理员——若无管理员权限则记为"未达：需管理员创建测试用户"）或至少全新 RESET_RUNE_DATA_DIR 下用 setup.exe /S 安装 → start → status → 卸载。
8. Explorer 重启后托盘图标：手工或 UIA 核实（P3 遗留），把结论写入。
