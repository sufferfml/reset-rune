# 信使任务开发计划

状态：核心、管理窗、投递宿主、双端模拟及 Codex 同桌面原生 IPC 路径已实现。核对日期：2026-11-08。当前 Codex 精确版本通过真实只读握手、owner/目标状态与发现核对；尚未进行真实发送验收。Claude 真实验证按用户要求延期，真实派发保持阻断。没有真实消息发送或备用重置测试。版本范围见[兼容记录](courier-compatibility.md)。

配套：[技术方案](courier-technical-design.md) · [现有验证范围](acceptance-matrix.md) · [界面约定](../design/README.md)。

## 1. 目标与验收定义

用户创建一项「信使任务」（Courier Tasks）：选择 Codex 或 Claude 桌面端中的一个明确聊天，填写文本并安排时间；应用到点尝试把文本发送到这个聊天，记录派发结果。

本功能交付的是「定时续发」，不是在独立 CLI 会话或云端执行工作。已发送只表示指定文本已被目标聊天接收，不表示 Agent 已完成工作、测试通过或产物正确。沿用桌面聊天的上下文与权限，应用不替用户批准 Agent 后续工具操作。

### 首版范围

| 能力 | 交付要求 |
| --- | --- |
| 目标应用 | Codex 桌面端；Claude Desktop 的 Code 聊天，非普通 claude.ai 聊天 |
| 目标聊天 | 从明确来源选定一个已有聊天；保存稳定标识，发送前重新确认；不支持「到点时的当前聊天」或新建聊天 |
| 内容 | 一段纯文本指令；支持中文、多行、引号和 emoji，保持原文；不直接执行 shell、不上传附件 |
| 时间 | 单次指定时刻、多久之后；相对时间保存时固定为绝对时刻，展示日期、时间和时区 |
| 管理 | 创建、编辑草稿/待发送/暂停项、逐条暂停/启用、删除、复制、打开目标聊天；发送中及终态只读，需复制为新任务 |
| 记录 | 待发送、已暂停、发送中、已发送、未发送、已错过、发送结果待确认；保留尝试原因和时间 |
| 重试 | 只重试确定未触发发送的可恢复情况；有固定截止时间，不能无限延长 |
| 本机运行 | 后台负责排期，正在运行的主应用按适配器通过 Codex IPC 或 AX 管线投递；关闭面板不影响投递，退出主应用后等待重新打开 |
| 分发 | 保持 reset-rune 的 macOS 原生、npm/DMG 同源方式；不引入常驻浏览器、Node 或新云服务 |

周期任务、额度恢复后触发、神符使用成功后触发、Windows 适配、批量导入 UsageWatch 数据、自动拉起已退出的主应用、跟踪 Agent 工作完成均不在首版。两种目标应用属于首版范围；一个适配器未通过门槛时，应明确未交付该部分，不能宣布双端完成。

现有登录启动设置只启动后台服务，不启动主应用投递宿主。首版用户登录后需自行打开主应用；本期不增加新的主应用登录项，此限制要在创建任务时说明。

### 使用流程

1. 打开「信使任务」，选择目标应用与明确聊天，查看标题、项目提示和可区分标识。
2. 填写发送文本与发送时间；不另设任务名称，列表与记录直接显示文本摘要。表单不提供延后期限选项，后台为新排期固定保留 15 分钟补发期限。核对所选通道的窗口行为：Codex 通常无需前台，恢复既有目标时可能发生系统导航；AX 路径可能切换并置前目标应用。
3. 点击唯一的「保存」按钮，即启用该任务与信使派发，不提供保存为暂停的入口。此前全局暂停的其他未来排期也会恢复，已过计划时刻的任务仍需重排；界面在保存前说明此行为。Codex 原生路径无需辅助功能权限，只有需要 AX 的可发送适配器才引导授权。
4. 到点后检查授权、宿主、精确聊天归属和忙碌状态，再尝试发送。Codex 通过桌面 owner 派发，不写入输入框；AX 路径还需检查草稿。
5. 在派发记录查看结果；「已发送」和「结果待确认」都提供「打开目标聊天」。

仅查看魔瓶、管理神符或使用 Codex 原生任务的用户不需要辅助功能权限。首次创建任务不改变「自动使用神符」授权，也不以备用重置测试任务。

### 已核实的技术路线调整

原方案拟用 AX 操作两端。开发核对发现：当前 Codex 的 AX 树不足以证明指定线程，但桌面自身有可精确路由到既有聊天 owner 的 IPC，并能返回目标状态与真实 turn 回执。因此 Codex 改用该通道，仍在原桌面聊天中工作，不另开 CLI/App Server。权限沿用桌面当前聊天设置，指令不添加正文标记；忙碌或待审批时等待。

目标 owner 尚未加载时，可在确认桌面和来源后定向打开已有聊天再核对；不会退回当前聊天或新建聊天。无需保持 Codex 前台；开始准备时 Codex 未运行则等待其重新打开。系统 URL 打开与桌面同时退出存在竞态，不能把后台打开配置当作系统级零启动/零激活保证。真实锁屏、送达和草稿保留效果仍需实发验收，不能由只读核对推导。

## 2. 主题与界面

主题语义：**魔瓶管补给，信使送指令，Agent 在聊天中工作，战报记录派发。**「信使任务」是本项目的设计类比，不声称是 Dota 2 的官方定时机制。

- 魔瓶与重置神符继续表示备用重置；蓝量继续表示真实额度。任务不消耗虚构神符，也不要求瓶内有符。
- 名称使用「信使任务 / Courier Tasks」；说明使用「选好聊天，留下指令，让信使到点送达」。
- 功能字段使用「目标应用」「目标聊天」「发送文本」「发送时间」。最晚发送时间仅在派发记录中用于核对证据；表单用一句短说明解释固定 15 分钟的补发期限，不再提供第二组时间设置。按钮使用「保存」「暂停」「打开目标聊天」，不以游戏用语替代关键操作。保存即启用，任务名称不再单独填写。
- 368px 主面板只新增摘要和入口，例如「信使任务 · 2 个待发送」「下次今天 21:00 · 总结本周提交」；任务异常须注明来自信使，不改变魔瓶库存图的含义。
- 列表、编辑器和派发记录放独立原生管理窗；这是对当前单面板设计的一项明确扩展，普通设置与神符明细仍原地展开。
- 主题通过小图、标题和克制文案表达，不加装备栏、养成、音效或常驻动画。本次不制作新美术；后续新增素材需遵守 assets/ARTWORK.md。

### 拟定交互默认值

新建、编辑、复制或重新安排的任务，后台统一将最晚发送时间固定为计划时刻后 15 分钟，不接受客户端自定义期限。表单仅保留发送时间与简短补发说明。已有 60 分钟期限的 v1 任务及历史保持原值，读取与恢复不迁移；再次保存或重排后使用 15 分钟。Codex 的已核对版本可由用户明确启用，界面同时说明未实发验收。

主应用退出、目标暂忙或通道暂不可用时等待；AX 路径遇锁屏/草稿也等待。Codex 原生路径不操作输入框，不要求解锁门禁；锁屏实际送达本轮未测试。所有路径都不改变锁屏设置、不阻止睡眠、不模拟鼠标防空闲。恢复条件满足且未过截止时可重试，过截止记为「已错过」。逐条或全局暂停后，重新启用已过计划时刻的任务必须重选发送时间，不立即补发。复制任务生成新 ID，默认未启用，时间重新确认。保存时要求计划时刻晚于当前时刻，确认期间时间已过则重新选择。

删除取消未发送计划，不立即删除已有派发证据；普通终态记录按条数和容量上限清理，未决证据不自动清理，记录页说明保留规则。消息可能已经发出时不能承诺撤回。未知结果提供人工核对，用户确认作为追加记录，不覆盖原始不确定证据，并解除该项的未核对阻断。确需再发时创建新任务并提示重复风险。

## 3. 现有资产与移植边界

来源是独立的 UsagewatchMac 仓库，而非 Usagewatch 云端/iOS 仓库。此次只读参考，不更改源项目、不读取真实登录令牌、不搬运用户聊天或任务数据。

| 资产 | 处理方式 |
| --- | --- |
| UsagewatchMac 的任务表单、模型、指定时间/延迟、停止和复制 | 参考交互与纯计算逻辑；不是直接照搬生产状态格式 |
| UsagewatchMac 的 ThreadSources、Sender、AX | 拆成 Codex/Claude 版本适配器，核对许可后复用合适代码；补上目标核对与回执缺口 |
| 原项目每秒轮询、防睡眠、零位移鼠标 | 不移植；采用现有一次性定时与系统事件 |
| 原项目按标题首个匹配、任意 turn/start 计数 | 不作为身份和送达证据；P0 必须找到可验证替代 |
| reset-rune 的后台、原子私有存储、鉴权 API、SSE、隔离测试 | 复用基础设施；任务状态与神符状态独立 |
| 现有 CodexTransport / RuneEngine | 保持账号、额度和备用重置职责，不加入桌面文本发送 |

UsagewatchMac 最低 macOS 14，而本项目为 macOS 13；其激活代码使用 14+ API，不能原样复制。原功能继续支持 13；信使的 13/14+ 激活路径及可支持系统范围在 P0 实测，不因本功能静默提高整个产品最低版本。

## 4. 分阶段开发

采用按风险放行的阶段，不在桌面版本和目标身份尚未确定时承诺日历工期。已完成不发送真实消息的代码、隔离验证及 Codex 真实只读核对；真实发送与发行验收仍未完成，不以其他阶段完成替代它。

| 阶段 | 工作 | 可审核产物与放行条件 |
| --- | --- | --- |
| P0：身份与权限验证 | 冻结目标版本、聊天来源和 schema；验证发前稳定身份、发后精确消息证据与跨渠道签名路径；Codex 核对 IPC peer/owner，AX 路径核对权限归属与 13/14+ 激活 | 分通道记录兼容矩阵、合成样本、证据规则和继续/阻断结论；真实发送另行验收，Claude 延期；标题匹配或全局日志计数不能过关 |
| P1：合同与调度 | 任务/运行模型、持久状态、截止时间、单实例领取、暂停、故障恢复；仅接假适配器 | 假时钟和故障注入通过；重启不重复发送，未知结果不补发，神符调度不受影响 |
| P2：桌面适配 | 主应用投递宿主、发现与定位；Codex 通过 owner 单次提交及关联回执；AX 管线检查草稿、操作一次按钮及核实回执 | 合成 Unix socket、可注入 AX 驱动与双端内存模拟验证对应链路；真实兼容测试另行授权，只用专用测试聊天；Claude 真实验证延期 |
| P3：产品界面 | 摘要入口、原生管理窗、表单、目标核对、按需授权、派发记录与通知 | 中英文、深浅色、键盘、长文本、长标题、待确认和退出语义检查通过 |
| P4：生命周期与分发 | 主应用退出/重开、后台重启、升级回退、损坏/磁盘满、两渠道授权和同机唯一宿主 | 最新记录保留；不因版本切换重发、不自动启动用户已退出的主应用 |
| P5：系统验收 | 双端兼容、真实时间、睡眠锁屏、用户切换聊天、并发输入、资源回归 | 逐项回执、已知限制及发布检查；用户另行授权后才执行签名、公证、提交或发布 |

发现某个版本缺少稳定目标识别或送达证据时，阻断该适配器并反馈缺口。不得为了完成计划退化成「搜到同名聊天就发」或切到后台新会话。

## 5. 验收矩阵

| 类别 | 必须覆盖的场景 |
| --- | --- |
| 目标正确性 | 相同标题、重命名、归档/删除、多个项目/窗口、不同本地来源、临时切换聊天；不回退当前或新建聊天 |
| 内容完整性 | 中文、多行、emoji、Unicode 组合字符、引号、重复文本；Codex 关联 owner 回执原文，AX 读回草稿与待发文本一致 |
| 不打扰用户 | Codex 不操作输入框，核对忙碌、owner 变化及取消；AX 检查已有草稿、投递期间输入/切窗，提交前中止，清理只限可证明属于本次的草稿 |
| 权限/状态 | 宿主退出、目标未安装/未登录、版本不支持、来源不可读；Codex 核对 IPC 身份/权限继承，AX 覆盖未授权、权限撤销和锁屏；Codex 锁屏送达另行实测 |
| 时间 | 保存相对时间、重启、时区/时钟变化、睡眠跨时刻、截止边界、唤醒与重连并发；截止不滑动 |
| 发送结果 | Codex 请求部分写出、响应丢失、错误 owner/turn/client ID；AX 按钮禁用或调用后输入未清空；两路均覆盖回执延迟、无关联证据、其他聊天并发和同文本用户消息 |
| 恢复 | 写盘失败、按发送前后崩溃、服务重启/换代、宿主断开、旧回执重放；未知不重发 |
| 授权独立 | 任务开启/神符关闭、任务暂停/神符开启、长 UI 操作不阻塞临期兑换 |
| 生命周期 | 关闭面板继续、退出主应用等待、重开截止内补发、停止后台阻断发送、升级回退不恢复旧任务快照 |
| 分发与资源 | npm/DMG 同一权限主体、原签名身份；隐藏面板释放视图，无每秒轮询或远期聊天扫描 |

所有自动化仅用合成聊天目录、假时钟、假适配器与本项目界面；模拟模式拒绝真实目标应用。用户已另行授权两端只读核对，随后要求 Claude 留待以后验证，已据此停止该端核对。该授权不包含输入或发送，详见兼容记录。真实发送仍须以后另行明确授权的专用测试聊天，不使用生产工作聊天，不使用真实备用重置。

## 6. 发布门槛与文档交付

- 同时明确支持的 Codex/Claude Desktop 版本、操作系统、架构、来源格式及限制；CLI 0.153.0 兼容不代表桌面端兼容。
- 「已发送」有目标关联证据；无法可靠区分用户同时发送相同文字时应待确认，不承诺任意外部副作用恰好一次。
- 两路都要求主应用运行、版本/来源可核对、目标明确且不忙；Codex 需可信 IPC owner，不要求 AX 或解锁门禁，真实锁屏送达尚未验收；AX 路径另需辅助功能授权、屏幕未锁和可操作控件。计划时间不是实时送达 SLA。
- 签名、公证、升级和实际发送证据分别记录。合成测试不能作为真实桌面兼容结论。
- 实现阶段同步根/原生模块导航、界面约定、用户 README 与验收记录；未实现期间用户 README 不列为可用功能。
