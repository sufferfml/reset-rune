# 验证范围

Bottled Reset Rune 的验证分为合成业务测试、隔离安装检查和真实环境观察。测试不使用真实账号的备用重置，不读取真实登录令牌，不以模拟结果证明线上兑换资格。

## 合成业务测试

| 范围 | 必须核对的行为 |
| --- | --- |
| 到期与时钟 | 窗口开始、恰好到期、过期、时区与时钟变化；到期后不发送消费请求 |
| 授权与暂停 | 默认关闭、明确开启、暂停立即关门禁、关闭过程不发送新请求 |
| 身份与库存 | 账号或工作区变化阻断；未知库存、缺少到期、重复 ID 和不完整明细不被当成完整库存 |
| 服务端结果 | 成功、无可重置窗口、指定次数不可用和结果未知分别处理 |
| 持久化与恢复 | 意图先落盘、回执先落盘、写失败不发送；重启恢复沿用原目标和幂等键 |
| 并发与唯一执行 | 同机只运行一个执行器，两个安装入口不重复兑换，异步操作之间保留事务互斥 |
| 调度 | 完整最早库存远期零周期查询；空或未知库存低频发现；状态读取不能推迟任务 |
| 显示 | 有符、空瓶、待确认分别显示，自动使用开关独立于库存；中英文、明暗外观和互斥展开不改变业务配置 |

```sh
npm test
swift test --package-path native
```

共享向量位于 `test/contracts`；参考实现位于 `test/reference`。假时钟测试与真实时间运行是两种证据，不能混用。

## 隔离安装与发行检查

| 范围 | 必须核对的行为 |
| --- | --- |
| 架构 | 两个应用分别包含 arm64 与 x86_64 的匹配可执行文件 |
| npm | 主包只选择匹配架构的平台包，英文 README 为默认，中文版使用外链；安装后 CLI 帮助和版本可运行 |
| DMG | 两份镜像只读挂载后应用结构正确，可拖入 Applications |
| 签名与公证 | 应用、helper 和 DMG 的签名有效；Apple 公证成功，票据可验证 |
| 跨渠道内容 | 同架构 npm 与 DMG 中完整签名应用的文件及模式一致 |
| 生命周期 | 模拟服务安装、启动、停止、升级、回退和卸载可恢复；操作记录不随程序回退 |
| 隔离 | 只清理本次创建的 `.mock` 服务、临时目录和子进程，不改变真实用户环境 |

```sh
node scripts/verify-native-artifacts.mjs
python3 scripts/smoke-native.py --seconds 120
python3 scripts/smoke-native-lifecycle.py
```

检查使用空白 `CODEX_HOME`、私有数据目录和合成 App Server。发行检查不运行真实账号的绑定、启用或兑换命令。

## 资源与真实环境

分别记录菜单栏与后台的空闲 CPU、物理内存占用、唤醒次数、完整下载量和磁盘占用；查询期间还应单列真实 Codex 及后代进程的成本。短时模拟空闲观察不能代替 24 小时运行或真实 Codex 查询测量。

睡眠恢复、网络恢复、最低系统版本和 Intel 硬件需要各自的真实环境证据。Rosetta 下的 CLI 检查不能代替 Intel 硬件验收。Codex 最终兑换资格以及低使用量时是否可用，不能由合成测试确认。

## 结果记录

本文件定义验收条件，不把未运行的检查标记为通过。每次发行应保留对应源文件、产物校验和、命令退出结果与隔离检查回执；本机回执存于 Git 忽略的构建目录。对外声称的验证范围必须与实际回执一致。

## 当前验证结果

以下历史结果仅覆盖现有神符发行版。「信使任务」开发验证另列在后，其验收见[开发计划](courier-development-plan.md#5-验收矩阵)与[技术方案](courier-technical-design.md#10-验证与尚待冻结事项)，不能据此认定任何桌面聊天发送能力已通过。

- 原生单元与合成协议检查通过；JavaScript 合同参考的 28 项检查通过。
- Apple 芯片与 Intel 的应用、helper 和 DMG 均通过 Developer ID 签名、Apple 公证及票据验证。
- 两种架构的 npm 平台包与 DMG 内的完整签名应用内容一致；隔离 CLI 帮助与版本检查通过。
- 模拟服务安装、重启、升级、回退和卸载检查通过，操作记录及最新设置保留，测试注册已清理。
- 120 秒合成空闲观察中，远期任务没有新增远程查询，状态订阅及暂停门禁正常；这不是 24 小时能耗或真实 Codex 查询测量。
- 真实备用重置、Intel 硬件和最低系统版本实机验收未在本轮执行。
